### G1 – Frisches SDK-Archiv direkt starten, ohne chmod

**Hypothese:** Das SDK-ZIP liefert den Unix-Launcher direkt ausführbar; der direkte Start funktioniert aus einem fremden Arbeitsverzeichnis mit Leerzeichen/Umlaut/Emoji; Bedienfehler enden vor Host-IO mit Exit 2.

- SDK-ZIP: `build/releases/interlis-java-sdk-0.2.0-SNAPSHOT.zip`, SHA-256 `b6efcbc6d6c73350bf70c19869025fce1776d6a5200da3ea4db30d162a112bae`.
- Entpackt mit `/usr/bin/unzip -q` nach `counterprobe/sdk space`; **kein chmod**.
- Arbeitsverzeichnis `counterprobe/Arbeits Ordner 😀`; Modelle `Good.ili` (gültig, aus `testdata/models/base24.ili`), `Bad.ili` (semantisch defekt, aus `testdata/models/broken24.ili`) und `-Leading Space 😀.ili`.

**Tatsächliche Ergebnisse:**
- `stat`: `cli/bin/interlis-compiler` ist `-rwxr-xr-x` (`0755`), `.bat` ebenfalls `0755`.
- Direkter Aufruf `cli/bin/interlis-compiler --help` → Exit 0, stdout 807 Bytes, stderr leer.
- `version --json` → Exit 0, `{"tool":"interlis-compiler",...}`.
- `check Good.ili` → Exit 0, stdout leer, stderr leer.
- `check Bad.ili` → Exit 1, stdout leer, Diagnose auf stderr (`ILI-SEM-0010`, `ILI-SYN-0002`; Rohkey ist CLI2-Arbeit).
- `interlis-compiler Good.ili` (alter Dateiaufruf) → Exit 2, stdout leer, `Example: interlis-compiler check <File.ili>`, `unknown command: Good.ili`.
- `check -o0 Good.ili` → Exit 2, stdout leer, `unsupported option: -o0`.
- `check -- "-Leading Space 😀.ili"` → Exit 0.
- Netz-Sentinel: lokaler HTTP-Proxy mit Positivkontrolle (`GET http://sentinel.invalid/control` geloggt); danach alter Dateiaufruf und `-o0` mit `JAVA_OPTS` auf den Sentinel → jeweils Exit 2, Sentinel-Log unverändert (keine zusätzliche Zeile).

**Ergebnis:** F1 ist behoben; der direkte Start ohne chmod und ohne Reparatur funktioniert.

### G2 – Echter negativer Lieferchecker und mutierter SDK-Consumer

**Hypothese:** Der Lieferchecker akzeptiert die neue Auslieferung nur mit ausführbarem Launcher; ein nicht ausführbarer oder verbotener Launcher muss scheitern. Der SDK-Consumer darf einen `0644`-Launcher nicht mehr mit `setExecutable` reparieren.

### F3 – Aktive Spezifikation nennt das Gradle-Modul als CLI-Programm (Muss, niedrige Schwere, offen)

- **Betroffene Kriterien:** CLI1-08, CLI1-09.
- **Beleg:** `docs/spec/18-cli-sdk-und-kompatibilitaetsadapter.md:129`:
  ```text
  interlis-compiler-cli format [--check] [--write] [--indent N] [--line-ending lf|crlf] <files...>
  ```

- **Reproduktion:**
  ```sh

  "$SDK" interlis-compiler-cli format Good.ili

  # Formatprüfung wird als Befehl akzeptiert
  ```

- **Erwartet:** `interlis-compiler format [--check] ...` (Programmname), nicht `interlis-compiler-cli`.
- **Erforderliche Korrektur:** In der aktiven Spezifikation das eine Token `interlis-compiler-cli` im Beispiel durch `interlis-compiler` ersetzen; keine Produkt-/Test-/Normänderung. Danach neuen Kandidaten erzeugen und CLI1 erneut prüfen.
